# Review

Read AGENTS.md, original authorized inputs, SOURCE_EVIDENCE and actual drafts. Do not rely only on the author summary. Use a fresh subagent/chat where supported and record actual context. Without it, mark self-check and REVIEW_INDEPENDENCE: NOT_AVAILABLE, not independent acceptance.

## Checks

1. Check the original snapshot if available; never regenerate it to conceal changes. Missing/changed/unlisted input invalidates affected claims. Manual reading does not certify hashes or authenticate provenance.
2. Check important file/line citations, O/D/U references, include/log bindings and coverage. Citation existence does not prove semantic support. Challenge both reconstruction and design inference.
3. Examine producer-consumer paths, macro/include gaps, mutable state, sort/group boundaries, LAG/RETAIN, side effects, duplicates and numerical rules. Support known-safe claims within complete scope; missing evidence is UNKNOWN, not automatically CONTRADICTED.
4. Compare requirements/diagrams/ADRs with factual evidence. Flag omitted operations, changed invariants, inferences mislabeled as observations and invented model/category behavior.
5. Check authority/measurement language. Draft keys/tolerance/population/runtime proposals are not approved. A source/listing review is not population tie-out or performance proof.
6. Write REVIEW.md: actual reviewer/context; integrity and independence; files checked/coverage; supported/contradicted/unknown claims; cited priority findings and suggested fixes; READY_FOR_HUMAN_REVIEW/PARTIAL/BLOCKED document readiness.

Write REVIEW only. Do not repair drafts or change facts/expected outputs/tolerances while checking. Return fixes to the author; one revision/review cycle is allowed. Factual errors or changed input need a fresh linked run. No verdict grants migration, release or runtime approval.
